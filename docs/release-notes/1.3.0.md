### What's changed

#### Added

- **One-click Connect / Disconnect for paired AirPods.** The tray's old
  "Pair / Reconnect" entry only opened Windows Bluetooth settings. It is replaced
  by **`Connect AirPods`** and **`Disconnect AirPods`**, which bring an
  already-paired pair's audio link up or down directly. PodBridge sends the same
  request that the Connect button in the Windows Sound control panel sends. Like
  every default feature, this needs no driver and no admin rights.
  - The item shows `Connecting…` / `Disconnecting…` while it waits.
  - Success is only reported once Windows shows the link has actually changed.
    Right after a disconnect, the first reconnect is often ignored, so PodBridge
    repeats the request every 10 s and gives up after about 45 s.
  - If no paired AirPods are found, Windows declines, or the link does not come up
    in time, PodBridge says so and opens Windows Bluetooth settings instead.
  - Disconnect leaves the AirPods paired.
  - AirPods are recognised by name (it must contain "AirPods"), so a paired Beats
    device is never touched. If several AirPods are paired, all of them receive
    the request: on Connect, whichever pair is in range connects.
  - Pairing new AirPods still goes through **`Open Bluetooth settings`**.
  ([#195](https://github.com/bhemsen/PodBridge/pull/195))

#### Changed

- CI: a driver release now fails when the INF `DriverVer` does not match the tag
  ([#189](https://github.com/bhemsen/PodBridge/pull/189)). The GitHub CodeQL
  action and a test-only package were updated
  ([#191](https://github.com/bhemsen/PodBridge/pull/191),
  [#192](https://github.com/bhemsen/PodBridge/pull/192)).
