### What's changed

An honesty release. Two features turned out to promise more than they deliver —
gesture remap on current firmware, and the advanced tier's true security cost —
and both now say what is actually true. Plus hardening for the optional driver.

#### Changed

- **Gesture remap is now labelled experimental.** On current AirPods Pro 2
  firmware the earbuds simply ignore the press-and-hold command: PodBridge sends
  it, nothing changes. The old wording told you the setting would "be re-applied
  the next time they reconnect" — a promise that never came true, because the
  re-send delivers a frame the device discards. The window now says so up front,
  reports only what was actually observed (an acknowledgement is not proof the
  gesture changed), and the feature is marked ⚠️ experimental in the README.
  Nothing about the protocol was guessed at or changed; fixing it properly needs
  further clean-room reverse-engineering on real hardware.
  ([#160](https://github.com/bhemsen/PodBridge/issues/160),
  [#184](https://github.com/bhemsen/PodBridge/pull/184))

- **The advanced tier now states its real cost — three machine-wide changes, not
  two.** Enabling the optional driver always required turning **Secure Boot off**
  (test-signing mode cannot be enabled while it is on), but nothing said so. That
  is the costliest of the three, because Secure Boot protects the boot path
  itself, and on a BitLocker-encrypted disk changing it can demand your recovery
  key — the guide now warns about both.

- **The installer refuses to weaken your PC for nothing.** If **Memory Integrity**
  (Core isolation) is on, Windows rejects a test-signed driver no matter what else
  you do — so you could have disabled Secure Boot, enabled test-signing, trusted a
  certificate, and still had a driver that never loads. The installer now checks
  before touching anything and stops, having changed nothing. It also reports
  WDAC policy enforcement, common on managed work PCs. Test-signing state is
  deliberately *not* probed: reading it means running `bcdedit`, and PodBridge's
  promise never to run it stays absolute.
  ([#186](https://github.com/bhemsen/PodBridge/pull/186))

#### Security

- **The optional driver's device permissions were too broad.** Access was granted
  to *Everyone*, so any service, network logon or anonymous caller on the machine
  could open the AAP channel and send arbitrary L2CAP traffic to your AirPods. It
  is now limited to the interactive logon session — which is all the tray app
  needs, and runtime use still requires no elevation. Affects only users who
  installed the opt-in Tier-2 driver.

- Hardened the driver's inbound path against an out-of-bounds read if the
  Bluetooth stack were ever to over-report a transfer size, and closed a window
  where a receive thread could be left running unreferenced.
  ([#186](https://github.com/bhemsen/PodBridge/pull/186))

#### Fixed

- Dependabot split the CodeQL action's `init` and `analyze` updates into separate
  pull requests, which broke code scanning because the two must move together.
  They are now grouped so the pair always arrives as one change.
  ([#183](https://github.com/bhemsen/PodBridge/pull/183))

#### Docs

- The advanced-tier guide gained a **recovery section**: the driver is
  demand-start and bound to a single Bluetooth node, so it cannot stop Windows
  booting — and if it ever misbehaves, Safe Mode comes up clean and
  `pnputil /delete-driver` removes it. It also shows how to check a crash dump and
  how to prove from Windows' own install log whether the driver was ever present
  on a machine at all.

Every default (Tier-1) feature keeps working with no driver and no admin, and is
unaffected by everything above.
